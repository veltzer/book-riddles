\section {Serving a map from many servers (System design)}

A farm of servers supplies a map application with data about streets and so forth.
The whole map does not fit on a single server, so the map has to be distributed among the servers.
Every request of the application asks for the data of a square of 1 mile by 1 mile, anywhere on the map.
To keep the application fast, every request must be answered by a single server.
How would you distribute the data among the servers?

\subsection{Solution}

If we just cut the map into disjoint squares, one per server, a request that falls on the border between two
squares (or on the corner of four squares) would need several servers. So the regions of the servers must overlap.

Let each server hold a square of side $s$ miles, and place these squares on a grid with a step of $d = s-1$ miles:
the server $(i,j)$ holds the square $[id, id+s] \times [jd, jd+s]$.
Neighboring squares overlap by exactly 1 mile.

A request for the square whose lower left corner is $(x,y)$ is sent to server $(\lfloor x/d \rfloor, \lfloor y/d \rfloor)$.
Indeed, if $i = \lfloor x/d \rfloor$ then $id \le x < id+d$, so $x+1 < id+d+1 = id+s$ and the whole range $[x,x+1]$ lies inside
the range $[id, id+s]$ of the server. The same goes for $y$.
Finding the server is a simple computation and needs no lookup at all.

The price is that the data is duplicated: every server holds $s^2$ square miles but is responsible for only $d^2$ of them,
so the total storage is multiplied by $\left(\frac{s}{s-1}\right)^2$.
The bigger each server's square, the smaller the waste: with $s=2$ the data is stored $4$ times, with $s=11$ only $1.21$ times.
So each server should hold as big a square as it can.

In practice the map is not uniform: a square mile in a city holds much more data and gets many more requests than a square mile of desert.
So instead of a uniform grid, the map can be cut into regions of different sizes (for example with a quad tree), small ones in dense areas and big ones in
sparse areas, as long as each server also holds the 1 mile strip to the right of and above its region, and every request goes to the region that holds its lower left corner. Popular regions can also be replicated on several servers to share the load.
